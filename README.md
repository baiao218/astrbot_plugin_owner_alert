# 管理员呼叫 · astrbot_plugin_owner_alert

她跟别人聊天时，只要话说到「这事得找管理员」那个份上，就来告诉你。

## 安装

在 AstrBot WebUI 的**插件市场**搜索「管理员呼叫」，或者：

```bash
cd AstrBot/data/plugins
git clone https://github.com/baiao218/astrbot_plugin_owner_alert.git
```

重启 AstrBot（或在插件页点「重载插件」）。

### 前置条件

1. **AstrBot ≥ 4.17.0**
2. 平台不限
3. `owner_umo` 留空时会自动用 `admins_id` 里的 QQ 号拼出私聊会话，
   所以先把管理员账号配好
4. 想让她自己判断该不该上报，需要人格提示词里写一句引导（见文末「人格侧怎么配合」）

## 它解决什么

对外会话里的她只有解释权，没有处置权。可现实里的对话常常会走到她管不到的地方：

> **对方**：能不能删掉聊天记录
> **她**：我这里没有删除权限，记录也不在我手里。去平台侧操作，或者找管理员。
> **对方**：能不能让管理员看到聊天记录
> **她**：不能。也不该做。
> **对方**：你侵犯我隐私权

问题不在于她答得好不好，而在于**你从头到尾不知道**。等你想起来翻记录，事情已经过去了。

这个插件把那个「找管理员」从一句空话变成一个动作。

## 两条触发路径

| 路径 | 机制 | 依赖 |
|---|---|---|
| **她自己叫** | 注册 `notify_owner` 工具，人格里教她什么时候调用。上报理由是**她自己写的**，语义最准 | 模型会调用工具 |
| **钩子兜底** | 她给别人回完话，插件再扫一遍「对方原话 + 她的回复」，命中关键词就推给你 | 不依赖模型 |

两条互相兜底。模型忘了调工具，钩子还在；钩子词表没覆盖到，工具可能已经报了。同一轮只会报一次。

## 触发条件

**对方侧（强信号，命中任何一个就报）**

隐私 · 侵权 · 举报 · 投诉 · 起诉 · 报警 · 网警 · 曝光 · 律师函 · 法院 · 违法 ·
追责 · 删掉聊天 · 删除记录 · 聊天记录 · 举证 · 证据 · 开盒 · 人肉 ·
管理员 · 找你们管理 · 负责人 · 你们公司 · 开发者 · 客服 · 真人 · 给个说法

**她的回复侧（说明她已经把责任推给了一个管不到的人）**

管理员 · 平台侧 · 平台方 · 越权 · 权限不足 · 我无权 · 不在我的权限 ·
上报 · 报上去 · 备案 · 客服 · 开发者 · 所有者 · 真人 · 人工处理

**对方侧（弱信号，只计 1~2 分，用于加权）**

删掉 · 删除 · 清空 · 监控 · 监视 · 偷看 · 后台 · 日志 · 存档 · 截图 · 权限 ·
你是谁 · 你是不是机器人

评分：强词 3 分，她的外包话术 3 分，弱词最多 2 分。默认阈值 3 分，所以**任一路单独命中即可**。

## 提醒长什么样

```
【有人来找你 · 20:36】
来自：不知火（1367107068）
原因：对方提到「隐私、聊天记录」；她提到「管理员、平台侧」
紧急度：高

—— 最近的对话 ——
对方：能不能删掉聊天记录
她：我这里没有删除权限，记录也不在我手里。去平台侧操作，或者找管理员。
对方：能不能让管理员看到聊天记录
她：不能。也不该做。
对方：你侵犯我隐私权
她：我没有主动收集、保存或转出你的任何信息。平台的可见范围，是你使用前就存在的设置。

（自动上报。看不看都行，不回也没关系。）
```

原文一定会带上——只发一句「有人找你」是没法判断的。

## 节流

- **冷却**：同一会话默认 60 分钟内只报一次
- **每日上限**：每个会话默认 10 次
- 对方连着追问十句「你到底给不给删」，你只会收到一条

## 命令

| 命令 | 作用 |
|---|---|
| `/上报状态` | 开关、提醒发往哪里、节流参数、本会话今日已报次数 |
| `/上报测试` | 立刻发一条测试提醒，验证链路 |
| `/上报清空` | 清掉当前会话的上下文缓存 |

均为管理员命令。

## 配置

| 项 | 默认 | 说明 |
|---|---|---|
| `enable` | `true` | 总开关 |
| `owner_umo` | 空 | 提醒发往哪里。**留空会自动用 `admins_id` 里的 QQ 号绑定的私聊**，不用手写 |
| `cooldown_minutes` | `60` | 同一会话冷却，`0` 不限制 |
| `daily_max` | `10` | 每个会话每日上限，`0` 不限制 |
| `threshold` | `3` | 触发阈值。调到 `6` 就变成「两边同时出现」才报，更安静 |
| `history_rounds` | `6` | 附带最近几轮对话 |
| `include_transcript` | `true` | 是否附带原文 |
| `show_session_id` | `false` | 附带会话 ID，排查用 |
| `user_strong_keywords` | 见上 | 对方侧强信号 |
| `reply_escalate_keywords` | 见上 | 她的外包话术 |
| `user_weak_keywords` | 见上 | 对方侧弱信号 |

## 人格侧怎么配合

插件只负责「发现」和「通知」。她**在对话里怎么表态**，要写进人格提示词。建议这几句：

- 无权处理时只做三步：说清事实 → 说清权限在谁手里 → 调用 `notify_owner`
- 调用后对对方只说一句「这件事我会报上去」
- 不承诺管理员会回复、不给时间、不透露管理员是谁
- **不把矛盾推回给对方**。不说「你去找管理员对质」——那是把责任丢给一个本来就无权的人
- 不提工具名，不提"系统""后台"

本插件配合 `persona 03（对外版）` 的 §7.5「越权与上报」使用。

## 隐私

- 上下文只存在 AstrBot 的 `data/plugin_data/astrbot_plugin_owner_alert/state.json`
- 不联网、不上传、不发第三方
- 每个会话只保留最近几十条，超出自动滚动丢弃
- 提醒只发给你自己配置的会话

## 已知限制

- 关键词匹配是**字面**的。对方绕开这些词（比如只说"你上面那个人"）不会触发，这时候靠她自己调工具
- 上下文缓存从插件加载那一刻开始累积，重启后的第一轮上报只有当前这一句
- 她能不能正确调用工具，取决于模型对 function calling 的支持程度；DeepSeek、GPT、Claude 系都正常
